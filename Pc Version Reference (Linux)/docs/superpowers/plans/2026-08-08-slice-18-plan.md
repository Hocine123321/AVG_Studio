# Slice 18 — The Quick panel: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a non-modal floating panel, reachable from every screen with one
keystroke, that pulls the Live List, a user-chosen slice of Settings, the
Preview panels, and Recent Errors out from behind navigation.

**Architecture:** one new backend document (`quick_settings.json`, a list of
ids, following `avg/config/channel_defaults.py`'s shape exactly) plus two
routes; on the frontend, one hook (`useSettingsData`) extracted out of
`Settings.tsx` with no behavior change, so the same value-resolution and
field-rendering machinery serves both the full Settings screen and the new
panel's Quick Settings tab; the panel itself is a portalled overlay mounted
once in `App.tsx`, holding five tabs (Live List — moved, not rebuilt; Quick
Settings — new; Preview — moved and relaid-out; Recent Errors — new; In
work — a disabled placeholder).

**Tech Stack:** Python 3.12 + FastAPI (backend), React 19 + TypeScript
(frontend), pytest, mypy, oxlint.

**Source spec:** `docs/superpowers/specs/2026-08-07-slice-18-quick-panel-design.md`

---

## Five calls this plan makes that the spec leaves open

The spec is explicit that one of these (#1) is open and records a safe
default. The other four are real design gaps the spec's prose doesn't
close; each is called here, with reasoning, in the same spirit.

**1. The upper-left corner conflict (spec's own §1 "A conflict to settle").**
Slice 19 hasn't landed yet — `web/src/Rail.tsx` still renders the logo as
`<div className="rail__logo" aria-hidden="true">A</div>`, not yet a button.
Per the spec's recorded default: the `<` goes at the rail's outer edge,
vertically below the logo, and the logo keeps the corner it already
occupies. Task 9 builds exactly that.

**2. Quick Settings' save model.** The spec says editing "writes exactly
where Settings would write it, through the same route" and that the panel
has no `.btn--primary`, but doesn't say whether an edit commits immediately
or batches. **Default: it batches, exactly like `Settings.tsx` — a local
`draft`, one `saveSettingsValues()` call, a plain (not primary) `.btn`
labelled "Save changes."** Reusing the identical batching model this
codebase already trusts (one atomic POST, no half-saved state on a failure)
is lower-risk than inventing a second commit-on-blur model for the same
underlying route, and the spec's own "never a parallel store" line reads
naturally as "same values, same route" rather than "same values, different
timing."

**3. Whether Quick Settings and Preview share live state.** Both tabs need
a `valueOf(id): string`. Built as **one `useSettingsData()` instance per
`QuickPanel` mount, shared by both tabs** (passed down as props), rather
than two independent instances. Reasoning: `Settings.tsx`'s own docstring
already establishes that a field "being edited feeds the live preview
instantly," and giving Preview a stale, separately-loaded copy of the same
values would silently break that expectation the moment both tabs are
touched in one panel session — the exact kind of two-copies-diverge risk
`CLAUDE.md` and the Slice 19 spec's §2.3 both warn about elsewhere.

**4. Quick Settings does NOT share live state with the full Settings
screen.** They are separate mounts (a floating panel vs. a routed screen)
with separate `useSettingsData()` instances, each independently loaded from
`GET /api/settings/values` on its own mount. If both happen to be open at
once (the panel can float over the Settings screen) and the same field is
edited in both before either saves, the later save wins, ordinarily. This
is accepted as a real but low-probability edge case, not built around —
cross-instance sync is a materially bigger feature than this slice asks
for, and no spec section requests it.

**5. Adding/removing an id in Quick Settings commits immediately**, via its
own `saveQuickSettings()` call — distinct from the batched value-edit draft
in #2 above. Membership in the list ("which settings appear here") is a
different, lower-stakes kind of change than a setting's VALUE, and batching
it into the same draft would mean a membership change is silently lost if
the user closes the panel without pressing "Save changes" for an unrelated
value edit. Immediate commit matches `channel_defaults.json`'s own
"replaced wholesale" nature better than batching would.

## Task 1: `quick_settings.json` — the backend document

**Files:**
- Create: `avg/config/quick_settings.py`
- Create: `tests/config/test_quick_settings.py`

**Interfaces:**
- Produces: `STARTER_PRESET: list[str]`, `load_quick_settings(path=None) -> list[str]`, `save_quick_settings(ids: list[str], path=None) -> None`, `default_quick_settings_path() -> Path`.

**Why:** spec §2 and §5 (mandatory). Modelled line-for-line on
`avg/config/channel_defaults.py` — same docstring shape, same "storage
only, resolution lives elsewhere" split, same atomic temp-file-then-
`os.replace` write. The one real difference: a missing file reads back as
`STARTER_PRESET`, not `[]` — spec §3.2: "Ships with a starter preset."

- [ ] **Step 1: Pick the starter preset and write the failing tests.**
  Five ids that already exist in `avg.core.settings_schema.SETTINGS` and
  plausibly are what someone reaches for mid-task: `video_form`,
  `length_preset`, `voice_id`, `image_provider`, `captions_enabled`. (This
  is a product judgement call, not a technical one — flagged as adjustable,
  not load-bearing on anything else in this plan.)

```python
"""avg/config/quick_settings.py - which settings the Quick panel shows.

Mirrors avg.config.channel_defaults exactly: one document, one owner,
replaced wholesale, atomic write. The one difference from that module: a
missing file reads back as STARTER_PRESET, not [] - this document always
has SOMETHING to show, per the design spec's "ships with a starter preset."

Storage only. Filtering an id that no longer exists in the catalogue
happens in avg/api/routes_settings.py, which is the one place that already
knows the catalogue - this module has no import on avg.core.settings_schema
and never will, for the same layering reason channel_defaults.py stays
storage-only.
"""

from __future__ import annotations

import json
import os
import tempfile
from contextlib import suppress
from pathlib import Path

STARTER_PRESET: list[str] = [
    "video_form",
    "length_preset",
    "voice_id",
    "image_provider",
    "captions_enabled",
]


def default_quick_settings_path() -> Path:
    base = os.environ.get("APPDATA") or str(Path.home() / "AppData" / "Roaming")
    return Path(base) / "AVG Studio" / "quick_settings.json"


def load_quick_settings(path: Path | None = None) -> list[str]:
    target = Path(path) if path is not None else default_quick_settings_path()
    if not target.is_file():
        return list(STARTER_PRESET)
    try:
        data = json.loads(target.read_text(encoding="utf-8"))
    except Exception:  # noqa: BLE001 - a broken document is not a crash
        return list(STARTER_PRESET)
    ids = data.get("ids") if isinstance(data, dict) else None
    if not isinstance(ids, list) or not all(isinstance(i, str) for i in ids):
        return list(STARTER_PRESET)
    return ids


def save_quick_settings(ids: list[str], path: Path | None = None) -> None:
    target = Path(path) if path is not None else default_quick_settings_path()
    target.parent.mkdir(parents=True, exist_ok=True)
    fd, tmp_name = tempfile.mkstemp(dir=target.parent, prefix=".quick-settings-", suffix=".tmp")
    try:
        with os.fdopen(fd, "w", encoding="utf-8") as handle:
            json.dump({"schema_version": 1, "ids": ids}, handle, indent=2, sort_keys=True)
        os.replace(tmp_name, target)
    except BaseException:
        with suppress(OSError):
            os.remove(tmp_name)
        raise
```

"""tests/config/test_quick_settings.py"""

from __future__ import annotations

from avg.config.quick_settings import STARTER_PRESET, load_quick_settings, save_quick_settings


def test_a_missing_document_reads_as_the_starter_preset():
    """The one deliberate difference from channel_defaults.py's `{}` -
    spec §3.2: "Ships with a starter preset.\""""
    import pathlib
    assert load_quick_settings(pathlib.Path("/nonexistent/nope.json")) == STARTER_PRESET


def test_a_corrupt_document_reads_as_the_starter_preset(tmp_path):
    path = tmp_path / "quick_settings.json"
    path.write_text("{not json", encoding="utf-8")
    assert load_quick_settings(path) == STARTER_PRESET


def test_a_malformed_ids_field_reads_as_the_starter_preset(tmp_path):
    path = tmp_path / "quick_settings.json"
    path.write_text('{"ids": "not a list"}', encoding="utf-8")
    assert load_quick_settings(path) == STARTER_PRESET


def test_saving_then_loading_round_trips(tmp_path):
    path = tmp_path / "quick_settings.json"
    save_quick_settings(["video_form", "image_provider"], path)
    assert load_quick_settings(path) == ["video_form", "image_provider"]


def test_saving_replaces_wholesale(tmp_path):
    path = tmp_path / "quick_settings.json"
    save_quick_settings(["a", "b"], path)
    save_quick_settings(["a"], path)
    assert load_quick_settings(path) == ["a"]


def test_saving_an_empty_list_is_allowed_and_round_trips(tmp_path):
    """The user removing everything is a valid state, not an error -
    it reads back as [], not as the starter preset re-appearing, which
    would make "remove the last one" impossible to actually do."""
    path = tmp_path / "quick_settings.json"
    save_quick_settings([], path)
    assert load_quick_settings(path) == []

## Task 2: The routes

**Files:**
- Modify: `avg/api/app.py` (new `quick_settings_path` param, `app.state.quick_settings_path`)
- Modify: `avg/api/routes_settings.py`
- Create: `tests/api/test_quick_settings_routes.py`

**Interfaces:**
- Produces: `GET /api/quick-settings` → `{"ids": [...]}`, unknown ids silently dropped; `PUT /api/quick-settings` → same shape, 400 on any id not in the catalogue.

**Why:** spec §5 (mandatory: "an unknown id dropped on read"). The
strict-on-write / tolerant-on-read split (this plan's own call, not
verbatim spec text): a `PUT` is a deliberate user action driven by a
picker that only ever offers real catalogue ids, so an unknown id there is
either a bug or a stale client and deserves a 400, exactly like
`POST /api/settings/values` already validates its whole batch before
writing anything; a `GET`, on the other hand, exists precisely to survive
a setting having been deleted out from under a stored list — spec's own
example: "three were deleted in one day on 2026-07-28."

```tsx
const PROVENANCE_TAGS: { source: LiveEntry["source"]; label: string }[] = [
  { source: "probed", label: "Verified" },
  { source: "catalogue", label: "Listed" },
  { source: "manual", label: "Added by me" },
  { source: "suggested", label: "Suggested" },
];

const [provenanceFilter, setProvenanceFilter] = useState<Set<LiveEntry["source"]>>(new Set());

function toggleProvenance(source: LiveEntry["source"]) {
  setProvenanceFilter((prev) => {
    const next = new Set(prev);
    if (next.has(source)) next.delete(source);
    else next.add(source);
    return next;
  });
}
```

## Task 8: `QuickSettingsTab.tsx`

**Files:**
- Create: `web/src/QuickSettingsTab.tsx`
- Modify: `web/src/api.ts` (add `getQuickSettings`/`saveQuickSettings`)

**Interfaces:**
- Consumes: `ctx`/`schema` from the shared `useSettingsData()` instance, plus the new `GET`/`PUT /api/quick-settings` routes.
- Produces: the user-chosen field rows (via `SettingsGroup`, unmodified) plus an "Add a setting" picker and a per-row remove control, plus a plain `.btn` "Save changes" for the batched value edits (decision #2 above).

**Why:** spec §3.2. This is the task where the extraction in Task 3 pays
for itself: rendering the chosen ids needs no new field code at all.

- [ ] **Step 1: `api.ts` additions.**

```ts
export interface QuickSettingsResponse {
  ids: string[];
}

export function getQuickSettings(): Promise<QuickSettingsResponse> {
  return apiGet("/api/quick-settings");
}

export function saveQuickSettings(ids: string[]): Promise<QuickSettingsResponse> {
  return apiPut("/api/quick-settings", { ids });

```

  (Check whether `apiPut` already exists in `api.ts` alongside
  `apiGet`/`apiPost`/`apiDelete`/`apiPatch` — if not, add it following the
  same four-line shape as `apiPatch`.)

- [ ] **Step 2: The component.**

```tsx
import { useEffect, useState } from "react";
import { getQuickSettings, saveQuickSettings } from "./api";
import SettingsGroup from "./SettingsGroup";
import Select from "./Select";
import type { SettingSpec } from "./api";
import type { SettingsCtx } from "./fields/types";

export default function QuickSettingsTab({ schema, ctx, dirtyCount, saving, saveError, handleSave }: {
  schema: SettingSpec[] | null;
  ctx: SettingsCtx;
  dirtyCount: number;
  saving: boolean;
  saveError: string | null;
  handleSave: () => void;
}) {
  const [ids, setIds] = useState<string[] | null>(null);
  const [adding, setAdding] = useState("");

  useEffect(() => {
    void getQuickSettings().then((r) => setIds(r.ids));
  }, []);

  async function addId(id: string) {
    if (!id || ids === null || ids.includes(id)) return;
    const next = [...ids, id];
    setIds(next);
    await saveQuickSettings(next);
  }

  async function removeId(id: string) {
    if (ids === null) return;
    const next = ids.filter((i) => i !== id);
    setIds(next);
    await saveQuickSettings(next);
  }

  if (schema === null || ids === null) return <p className="home__empty">Loading…</p>;

  const specs = ids.map((id) => schema.find((s) => s.id === id)).filter((s): s is SettingSpec => s !== undefined);
  const addable = schema.filter((s) => !ids.includes(s.id));

  return (
    <div className="quickpanel-settings">
      {specs.length === 0 ? (
        <p className="home__empty">Nothing here yet — add a setting below.</p>
      ) : (
        <SettingsGroup title="Quick Settings" specs={specs} ctx={ctx} />
      )}

      <div className="quickpanel-settings__manage">
        <Select
          value=""
          ariaLabel="Add a setting"
          options={[{ value: "", label: "Add a setting…" }, ...addable.map((s) => ({ value: s.id, label: s.label }))]}
          onChange={(v) => void addId(v)}
        />
        {ids.map((id) => (
          <button key={id} type="button" className="btn btn--sm" onClick={() => void removeId(id)}>
            Remove {schema.find((s) => s.id === id)?.label ?? id}
          </button>
        ))}
      </div>

      {saveError && <p className="settings__save-error">{saveError}</p>}
      <button type="button" className="btn" disabled={dirtyCount === 0 || saving} onClick={handleSave}>
        {saving ? "Saving…" : `Save changes${dirtyCount ? ` (${dirtyCount})` : ""}`}
      </button>
    </div>
  );
}
```

  (The per-id "Remove" button list is a first-pass layout, not a final
  one — Task 10's design-language pass may fold this into a more compact
  row-level remove control, e.g. an `x` beside each field row rather than
  a separate button list below. Flagged rather than pre-decided, since it
  is a pure styling question with no behavioral stakes.)

## Task 9: `QuickPanel.tsx` — the shell, and wiring it in

**Files:**
- Create: `web/src/QuickPanel.tsx`
- Modify: `web/src/App.tsx` (mount `QuickPanel`, remove the `livelist` `Screen` variant and its branch, remove `onOpenLiveList` wiring)
- Modify: `web/src/Rail.tsx` (the `<` open button)

**Interfaces:**
- Produces: open/closed state, active tab, drag position — all in `localStorage` per spec §2, clamped on read and on drag.
- Consumes: `useSettingsData()` (one instance, shared by the Quick Settings and Preview tabs per decision #3).

**Why:** spec §1–2. This is where the five tabs, the drag/clamp behavior,
and the `<`/Escape open-close mechanics come together.

- [ ] **Step 1: Position state and clamping.**

```ts
const POSITION_KEY = "avg.quickpanel.position";
const OPEN_KEY = "avg.quickpanel.open";
const TAB_KEY = "avg.quickpanel.tab";

interface Position { x: number; y: number }

function clamp(pos: Position, panelW: number, panelH: number): Position {
  const maxX = Math.max(0, window.innerWidth - panelW);
  const maxY = Math.max(0, window.innerHeight - panelH);
  return { x: Math.min(Math.max(pos.x, 0), maxX), y: Math.min(Math.max(pos.y, 0), maxY) };
}
```

  Read on mount (a window resized smaller between sessions must not
  restore the panel off-screen — spec §2's own line) AND on every drag
  end and on a `resize` listener while open.

- [ ] **Step 2: The shell.**

```tsx
import { useEffect, useRef, useState } from "react";
import { createPortal } from "react-dom";
import { useSettingsData } from "./useSettingsData";
import LiveList from "./LiveList";
import QuickSettingsTab from "./QuickSettingsTab";
import PreviewTab from "./PreviewTab";
import RecentErrorsTab from "./RecentErrorsTab";
import { IconArrowLeft } from "./Icons"; // or a new chevron - see Task 10

type Tab = "livelist" | "quicksettings" | "preview" | "errors" | "inwork";

export default function QuickPanel() {
  const [open, setOpen] = useState(() => localStorage.getItem(OPEN_KEY) === "1");
  const [tab, setTab] = useState<Tab>(() => (localStorage.getItem(TAB_KEY) as Tab) ?? "livelist");
  const [position, setPosition] = useState<Position>(() => {
    try {
      const raw = localStorage.getItem(POSITION_KEY);
      return raw ? (JSON.parse(raw) as Position) : { x: 90, y: 60 };
    } catch {
      return { x: 90, y: 60 };
    }
  });

  const settingsData = useSettingsData();

  useEffect(() => { localStorage.setItem(OPEN_KEY, open ? "1" : "0"); }, [open]);
  useEffect(() => { localStorage.setItem(TAB_KEY, tab); }, [tab]);
  useEffect(() => { localStorage.setItem(POSITION_KEY, JSON.stringify(position)); }, [position]);

  // Escape closes it - spec §1: "a floating thing that cannot be
  // dismissed from the keyboard is a trap." Global, not focus-scoped:
  // the panel is non-modal, so focus may well be on the page behind it.
  useEffect(() => {
    if (!open) return;
    function onKey(e: KeyboardEvent) {
      if (e.key === "Escape") setOpen(false);
    }
    window.addEventListener("keydown", onKey);
    return () => window.removeEventListener("keydown", onKey);
  }, [open]);

  // Re-clamp on resize while open, per spec §2.
  useEffect(() => {
    if (!open) return;
    function onResize() {
      setPosition((p) => clamp(p, PANEL_WIDTH, PANEL_HEIGHT));
    }
    window.addEventListener("resize", onResize);
    return () => window.removeEventListener("resize", onResize);
  }, [open]);

  // ... drag handling: pointerdown on the header starts tracking,
  // pointermove updates `position` through `clamp`, pointerup ends it.
  // See Task 9 Step 3 below for why this is a plain listener pair rather
  // than a drag library.

  return (
    <>
      <button
        type="button"
        className="quickpanel-toggle"
        aria-expanded={open}
        aria-label={open ? "Close quick panel" : "Open quick panel"}
        onClick={() => setOpen((v) => !v)}
      >
        {/* `<` glyph - see Task 10 for whether this is a new Icons.tsx
            entry or a rotated IconChevron (Slice 17 already added one). */}
      </button>
      {open &&
        createPortal(
          <div
            className="quickpanel"
            style={{ left: position.x, top: position.y }}
            role="dialog"
            aria-label="Quick panel"
          >
            <div className="quickpanel__header">{/* drag handle */}</div>
            <div className="quickpanel__tabs" role="tablist">
              {/* five tab buttons, "In work" disabled and unclickable */}
            </div>
            <div className="quickpanel__body">
              {tab === "livelist" && <LiveList />}
              {tab === "quicksettings" && (
                <QuickSettingsTab
                  schema={settingsData.schema}
                  ctx={settingsData.ctx}
                  dirtyCount={settingsData.dirtyCount}
                  saving={settingsData.saving}
                  saveError={settingsData.saveError}
                  handleSave={settingsData.handleSave}
                />
              )}
              {tab === "preview" && <PreviewTab ctx={settingsData.ctx} />}
              {tab === "errors" && <RecentErrorsTab />}
            </div>
          </div>,
          document.body,
        )}
    </>
  );
}
```

  `LiveList` here takes no `onBack` prop (Task 5 already removed it) —
  confirm that call site matches the narrowed signature.

- [ ] **Step 3: Drag, without a new dependency.** Same reasoning `Select.tsx`
  gives for portalling rather than pulling in a library: this app has no
  UI-widget dependency, and a drag gesture is `pointerdown`/`pointermove`/
  `pointerup` with an offset captured on down and `clamp()` applied on
  every move — a dozen lines, not a package. Implement on the header
  element only (spec doesn't ask the whole panel body to be a drag
  handle, and making it one would fight clicking the tabs and fields
  inside).

- [ ] **Step 4: `Rail.tsx` — the `<` button.** Per this plan's decision #1
  (the spec's own recorded safe default): rendered inside `.rail`, right
  after `.rail__logo`, as a small absolutely-positioned control at the
  rail's outer (right) edge — NOT one of the 48px `.rail__item` icons in
  the main column, since it belongs to a different, cross-cutting
  concern (a global panel toggle, not a section of the app) and spec §1
  literally says "the `<` sits at its edge." `QuickPanel` owns the
  open/closed state, so this is either (a) `QuickPanel`'s own toggle
  button rendered THROUGH a prop/portal into the rail's DOM position, or
  (b) `Rail.tsx` grows an `onToggleQuickPanel`/`quickPanelOpen` prop pair
  and `App.tsx` lifts the open state up to pass to both. **Pick (b)** —
  it keeps `QuickPanel` as a single self-contained component (matching
  how `StatusBar` already owns its own local UI state) at the cost of one
  small prop pair on `Rail`, rather than teaching `Rail` to render
  something owned by a sibling component's internals.

  This means `QuickPanel`'s `open` state (Step 2 above) actually needs
  to be LIFTED to `App.tsx` and passed down as a prop, with `Rail`
  receiving `onToggleQuickPanel`/`quickPanelOpen` and `QuickPanel`
  receiving `open`/`onOpenChange` instead of owning `open` itself — the
  `localStorage` read/write for `OPEN_KEY` moves to `App.tsx` alongside
  it. (Written here as a correction to Step 2's sketch above, which
  drafted `open` as fully local before this step's own reasoning ruled
  that out — a real instance of "build it, then find the seam is in the
  wrong place," recorded rather than silently fixed.)

- [ ] **Step 5: `App.tsx` wiring.** Remove `{ name: "livelist" }` from the
  `Screen` union and its `else if (screen.name === "livelist")` branch;
  remove `onOpenLiveList` from the `<Settings .../>` call. Mount
  `<QuickPanel open={quickPanelOpen} onOpenChange={setQuickPanelOpen} />`
  once, beside `<StatusBar>` and `<Transport>` (same sibling level,
  outside `.app-shell__content` so a screen change never unmounts it —
  spec §1: "It lives in `App.tsx` beside the shell... switching screens
  never unmounts it or loses its tab and position").
