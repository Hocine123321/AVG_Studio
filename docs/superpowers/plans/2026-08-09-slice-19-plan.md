## Two decisions this plan makes that the spec left open

The spec flags both explicitly (§2.5, §7) rather than assuming. Both are
addressed with a recommendation below, not silently resolved — **confirm
before Task 2 starts**, since everything after it depends on the answer.

**1. `settings_source` is removed.** Recommended, matching the spec's own
one-sided argument in §2.5: keeping it means the resolver special-cases it,
and "no field resolved by looking in two places" becomes untrue in two
different ways instead of one. It is a real `SettingSpec` today
(`avg/core/settings_schema.py:184-200`, id=`settings_source`, scope=`channel`,
group=`app`) — removing it means deleting that catalogue entry, not just
retiring some resolver logic, and four existing tests
(`tests/api/test_routes_settings.py:498-551`) that assert its behaviour get
replaced, not patched.

**2. The Global/Channel toggle's write path is new API surface the spec
describes only conceptually** (§3: "In global mode it edits the defaults
document directly"). No route does that today — `POST
/api/settings/port-to-global` is a one-way channel-to-defaults *snapshot*,
never a live target for edits. Proposed shape, designed to reuse the same
resolver rather than add a second one (see Task 1's note): `GET
/api/settings/values` gains an optional `?scope=global` query param, and
`POST /api/settings/values`'s body gains an optional `target: "channel" |
"global"` field (default `"channel"`, so every existing caller is
unaffected). Full shape in Task 3.

## Task 1 — `resolve_channel_settings`, the one resolver

**Where:** `avg/core/settings_schema.py`, beside `channel_defaults()` (the
existing function of that near-identical name returns `{id: spec.default}`
only — do not confuse the two; this task adds a *new*, differently-named
function, it does not touch `channel_defaults()`).

**Why here and not `avg/api/`:** `avg/pipeline/` and `avg/core/` never
import from `avg/api/` (confirmed: zero hits for `from avg.api` anywhere
under `avg/pipeline/`, `avg/core/`, `avg/config/`). The resolver has to be
reachable from both the API layer and every phase file, so it lives at or
below `avg/core/`, not above it.

**Shape — pure, two dicts in, one dict out, no I/O:**

```python
def resolve_channel_settings(
    channel_settings: dict[str, Any], defaults: dict[str, Any]
) -> dict[str, Any]:
    """The one resolver (Slice 19 spec §2.3): for every scope="channel"
    SettingSpec, the channel's own value if the key is present there,
    otherwise the app-wide defaults document's value if present THERE,
    otherwise the SettingSpec's own default. Absence is the only
    inheritance signal - `channel_settings.get(id, ...)` would treat an
    explicitly-stored empty string as absent, which is exactly the legacy
    bug this function exists to not reintroduce; `in` is checked, not
    truthiness.

    Pure and I/O-free on purpose: callers own fetching both dicts (a
    channel's `.settings`, and `avg.config.channel_defaults.load_defaults()`),
    so this function has no path to the filesystem and no path to
    `avg.config.channels` - every caller, api or pipeline, can use it with
    nothing beyond stdlib dicts.
    """
    return {
        spec.id: (
            channel_settings[spec.id]
            if spec.id in channel_settings
            else defaults.get(spec.id, spec.default)
        )
        for spec in SETTINGS
        if spec.scope == "channel"
    }
```

**Note for Task 3:** the Global-mode read (decision #2 above) reuses this
exact function with the arguments swapped: `resolve_channel_settings(
load_defaults(), {})` — the defaults document standing in as the "channel"
argument, with nothing above it. One function, two calls, not two
functions.

**Tests (`tests/core/test_settings_schema.py` — new file, or append if a
suitable one exists; check first):**
- key present in channel wins over both defaults and spec default
- key absent from channel, present in defaults, wins over spec default
- key absent from both falls to `SettingSpec.default`
- **an empty string stored against an owned key returns as an empty
  string** — §2.2's whole point, the one test that would have caught the
  legacy bugs. Explicitly: `resolve_channel_settings({"length_preset":
  ""}, {"length_preset": "90s"}) == {..., "length_preset": ""}`, not `"90s"`.
- a key present in `defaults` but not a `scope="channel"` spec at all is
  ignored (the function only ever returns catalogue channel-scope ids)

**Build, test, commit.**

## Task 3 — Wire the resolver into `routes_settings.py`; the ownership routes; the Global-mode read/write

**3.1 Replace `_channel_values`:**

```python
def _channel_values(app_state: Any) -> dict[str, Any]:
    active_id = channels_config.active_channel_id(app_state.settings_path)
    channel = channels_config.get_channel(active_id, app_state.channels_dir) if active_id else None
    own = channel.settings if channel is not None else {}
    defaults = channel_defaults_config.load_defaults(getattr(app_state, "channel_defaults_path", None))
    return resolve_channel_settings(own, defaults)
```

No more `settings_source` read, no more whole-document switch. `own = {}`
when no channel is active resolves everything to `defaults` then
`spec.default` — same graceful "no active channel" shape the route already
promises elsewhere.

**3.2 `GET /api/settings/values?scope=global`:** when the query param is
`"global"`, return `resolve_channel_settings(defaults, {})` for the
`"channel"` key instead of the channel-resolved view. `active_channel_id`
stays in the payload either way (the toggle needs to know whether a channel
exists at all, to grey itself out per §3's "disabled, with a reason, when
no channel is active").

**3.3 `POST /api/settings/values` gains `target: Literal["channel",
"global"] = "channel"`** on `SettingsValuesUpdate`. When `target ==
"global"`: skip the "is a channel active" guard entirely (editing the
defaults document needs no active channel — it is the one place ownership
"does not apply because there is nothing above it to inherit from," per
§3), read-modify-write `channel_defaults_config`:
`defaults = load_defaults(path); defaults.update(channel_updates);
save_defaults(defaults, path)`. `app_updates` behave identically regardless
of `target` — app-scope settings were never part of this toggle.

**3.4 New route — release ownership:**

```python
@router.delete("/api/settings/values/{setting_id}")
async def release_setting(setting_id: str, request: Request) -> dict:
    """Release ownership of one channel-scope setting - deletes the key
    from the active channel's own document, so it goes back to reading
    the app-wide defaults (or the catalogue default) per
    `resolve_channel_settings`. The other half of §2.4's "one mechanism,
    two verbs": taking ownership is already just an ordinary write
    through POST /api/settings/values (nothing new needed there), this is
    the delete verb the old whole-document switch never needed."""
    app_state = request.app.state
    spec = get_spec(setting_id)
    if spec is None or spec.scope != "channel":
        raise HTTPException(status_code=400, detail=f"not a channel-scope setting: {setting_id!r}")
    active_id = channels_config.active_channel_id(app_state.settings_path)
    channel = channels_config.get_channel(active_id, app_state.channels_dir) if active_id else None
    if channel is None:
        raise HTTPException(status_code=400, detail="no active channel — nothing to release")
    channel.settings.pop(setting_id, None)  # already-absent is not an error
    channels_config.save_channel(channel, app_state.channels_dir)
    return _values_payload(app_state)
```

**3.5 `port_to_global` (routes_settings.py:1184-1223): no behavioural
change**, but its own `spec.id != "settings_source"` exclusion line
(1217) is now dead — that spec no longer exists, so the condition is
always true. Remove the now-meaningless clause rather than leave a
comment about a concept that no longer exists in the catalogue.

**Tests (`tests/api/test_routes_settings.py`):**
- Delete the four `settings_source`-based tests (lines 498-551), replaced
  by tests against the new shape: a key present in the channel wins; a key
  absent from the channel and present in defaults resolves from defaults;
  absent from both resolves to spec default; **empty string stored against
  an owned key returns as empty string, never inherited**.
- `DELETE /api/settings/values/{id}` releases the key and nothing else (a
  sibling key untouched); releasing an already-absent key is a no-op, not
  a 404; releasing an unknown/app-scope id is a 400.
- `?scope=global` GET reflects the defaults document, not the channel's;
  `POST ... {target: "global"}` writes to the defaults document and does
  **not** touch the active channel's own document; a `target: "global"`
  write needs no active channel (unlike a `target: "channel"` write, which
  still 400s with none active).

**Build, test, commit.** The build should be green again after this task —
it is what makes Task 2's expected breakage temporary.

## Task 6 — The drift test

Mirrors `tests/core/test_artifacts.py`'s `test_every_artifact_path_is_one_
clone_take_copies` in spirit, but the two things being compared are code
paths, not two data tables — so this is a source scan, not a set diff.

```python
# tests/core/test_settings_schema.py (or a new tests/core/test_resolver_drift.py)

_ALLOWED_RAW_READERS = {
    # The resolver's OWN construction of its first argument - reading
    # `channel.settings` here is what the resolver resolves, not a reader
    # bypassing it.
    "avg/api/routes_settings.py",
}

def test_no_reader_bypasses_the_resolver():
    """§2.3's whole risk: a second, uncoordinated copy of the fallback
    chain would not announce itself. This is what announces it - every
    `.settings.get(` or `.settings[` under avg/pipeline/ or avg/api/,
    outside the one file allowed to build the resolver's own input, is a
    reader that skipped resolve_channel_settings."""
    pattern = re.compile(r"\.settings\.get\(|\.settings\[")
    offenders = []
    for path in (*Path("avg/pipeline").rglob("*.py"), *Path("avg/api").rglob("*.py")):
        rel = path.as_posix()
        if rel in _ALLOWED_RAW_READERS:
            continue
        for lineno, line in enumerate(path.read_text(encoding="utf-8").splitlines(), 1):
            if pattern.search(line):
                offenders.append(f"{rel}:{lineno}")
    assert offenders == [], f"reads channel.settings directly, bypassing resolve_channel_settings: {offenders}"
```

This needs one real exception written INTO the allowlist with a comment
explaining it, not skipped silently: `routes_settings.py`'s `port_to_global`
(line ~1209, see Task 3.5) legitimately reads `channel.settings[spec.id]`
raw — porting snapshots what the channel *itself* owns, not the resolved
view, so it is correct for this one line to bypass the resolver on purpose.
Since the allowlist above is file-level, not line-level, and this file
also legitimately builds the resolver's own input at `_channel_values`,
both are already covered by allowing the whole file — narrower,
line-level exclusion is unnecessary here since every read left in this
file after Task 3 is one of those two legitimate cases.

Run this test *before* writing it as a specification — i.e., run the scan
manually against the Task-5-complete tree first, confirm it finds zero
offenders, then commit the test. If it finds something, that is Task 5
leaving a straggler, and the straggler gets fixed in Task 5's own commit
territory (amend, don't carry it forward as a "known gap").

**Build, test, commit.**
