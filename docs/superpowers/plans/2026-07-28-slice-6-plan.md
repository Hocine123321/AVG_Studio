## 6A — the phase spine  ✅ ready to build

Make Studio show Script as a group of two rows (Draft, Segmentation) with a
`partial` group state, **without changing the pipeline's data model.**

### Why display-only is safe

`ScriptPhase.run()` already does both passes internally: pass 1 writes
`script/narration.txt`, pass 2 writes `script/scenes.json`. Keeping one
`script` phase means **no migration, no id renumbering**, `invalidates="script"`
(two settings) stays correct, `legacy_import`'s alias map stays correct, and
the ten existing projects on disk keep loading. The only thing given up is
re-running segmentation alone — which nothing asks for today.

### Task 1 — `script_substate()` helper

In `avg/pipeline/phases/writing.py` (it already owns both filenames), add a
pure function:

```python
def script_substate(script_dir: Path) -> Literal["pending", "partial", "done"]:
```

- both files present → `"done"`
- `narration.txt` only → `"partial"`
- neither → `"pending"`

Takes the **script directory**, not a project — so a caller can point it at a
take's folder (`avg.core.takes.take_folder`) as easily as the project root.
No I/O beyond two `is_file()` checks. Pure, trivially testable.

### Task 2 — surface it on the API

`GET /api/projects` currently returns `{"projects": [ProjectDoc, ...]}`,
serialized straight from the model. Add a per-project `script_substate` key
computed **at request time**.

**It must not go on `ProjectDoc`.** That model is persisted by
`save_project`, and a derived value in a persisted document is a second
source of truth that will drift from the files. Build the response dicts in
the route instead.

Take-scoping: resolve the folder for the project's **current take** when it
has one, else the project root — matching how the rest of the API treats
`current_take_id`.

### Task 3 — `phases.ts` becomes a tree

Give `web/src/phases.ts` the mockup's shape:

```ts
export const PHASE_DEFS = [
  { key: "brief", label: "Brief" },
  { key: "script", label: "Script", sub: [
      { key: "draft", label: "Draft" },
      { key: "segmentation", label: "Segmentation" } ] },
  { key: "director1", label: "Director I" },
  ...
];
```

Keep a flat `PHASE_ORDER` derived from it for existing callers rather than
editing every call site. Port `leavesOf` and `groupStatus` from the mockup
(lines 673-681) — but note the sub-keys `draft`/`segmentation` are **frontend
labels only**; the backend has no such phase keys.

> This file is already a second copy of phase order, which
> `avg/pipeline/registry.py` exists to forbid, and this task makes it a
> richer copy. Serving phase defs from an endpoint would fix it properly. Not
> mandated here — raise it with the user, and if declined, leave a comment in
> `phases.ts` saying the duplication is known and deliberate.

### Task 4 — Studio renders the group

`web/src/Studio.tsx:475` maps `PHASE_ORDER` to `.phase-row` elements. Render
group rows with indented sub-rows, and compute the group's status with
`groupStatus`. The `partial` node style is in the mockup at CSS lines 180-192
(a half-filled conic-gradient node); port it into `tokens.css`.

Live runs need no new event — `ScriptPhase` already emits `percent=0
"Writing narration..."` and `percent=50 "Segmenting into scenes..."`, so a
live script phase past 50% is in segmentation.

### Task 5 — do not break the re-roll dropdown

`web/src/NewTakePanel.tsx` builds its "Re-roll a phase" `<select>` from
`PHASE_ORDER`. The backend validates `reroll_from` against `BY_KEY` and
**400s on an unknown key**. The dropdown must keep offering `script`, never
`draft` or `segmentation`. Add a test or a comment so a future edit does not
quietly start sending leaf keys.

Must stay at **537 or higher** — new tests for `script_substate` and the
route should push it up. Then `npm run build && npm run lint` in `web/`, and

## 6C — the shell  ⚠ blocked on open questions 1 and 3

The restyle plus the remaining features.

- **Restyle** (blocked on Q1): rail 58→74px, larger radii, auto-fill grid,
  Home kicker + 38px Caprasimo title, toasts, search box, device-frame
  player. Mechanical once the shadow question is answered.
- **Health / Components**: FFmpeg, Pillow, moviepy rows with state, a
  recheck action, a health cache. No health module exists. Worth real weight
  — it would have caught the Gemini zero-quota account before a video failed.
- **Bulk select + archive**: `ProjectDoc` has no `archived` field. Needs the
  flag, persistence, and Home selection state.
- **"Run again" (Q3)**: a per-phase re-run **already ships** — `POST
  /api/projects/{id}/takes` accepts `reroll_from`, and `NewTakePanel.tsx`
  has a "Re-roll a phase" dropdown. It treats the chosen phase as a *start*
  phase and re-runs everything downstream. The only missing capability is the
  exact single-phase run (`runner.run(only=...)`, which has no route). Ask
  which the user means before adding a second control that overlaps the
  first.
- **Theme wiring**: the catalogue offers nine theme values, `web/src/theme.ts`
  implements two (`night`, `day`), and `useTheme` reads `localStorage` and
  never reads the settings document. **All nine catalogue values are inert
  and the wiring is missing on both ends.** Treat as "connect the theme
  setting to the theme system", not "fix a stray value".
